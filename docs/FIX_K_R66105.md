## 2. К2 — первый экран

### К2а — баг каскада height:900px (подтверждён живым замером аудита)
`styles.css:217` задавал `.hero-image-wrap{…width:900px;height:900px…}` — остаток декоративного слоя с `content:''` (мёртвый legacy-hero, находка С2). Консолидированное правило `:759` (66.49) переопределяло width/position, но **не height** → computed **900px** при картинке **223px** @390w → мёртвая зона ~677px.

**Фикс**: `height:auto` в консолидированном правиле (последнее по каскаду). `left:50%`+`translateX(-50%)` **не тронуты** — это механика центрирования (обёртка шириной до 1180px центрируется в .hero). CLS: у `<img>` сохранены width/height-атрибуты — резерв места не зависит от обёртки.

**Живой замер после фикса** (Playwright, локальная сборка):
- @390: `.hero-image-wrap` computed **222.625px** (= картинка 223px; было 900px);
- @1440: **673.891px** (= картинка 674px);
- transform центрирования цел (`matrix(1,0,0,1,-195,0)` @390).

### К2б — первый экран не продавал продукт
Claim и CTA были вне вьюпорта 1440×900 И 390×844; кнопка игры — на 87% глубины; единственный интерактив выше фолда — fund-bar (ask без proof).

**Фикс** (RU+EN):
1. `.hero-claim` ВЫШЕ арта: value proposition («Историческая ролевая игра по мотивам Руси XV века: выживание в деревне, расследования и бои по BRP d100 — прямо в браузере») + кнопка «Играть в браузере» (класс btn-game-start, сжатый модификатором).
2. `.nav-cta` — компактная золотая кнопка «⚔️ Играть» в sticky-шапке (перед переключателем языка).

**Живой замер** (после фикса):
- 390×844: claim 115–303px, кнопка **224–287px** — глубоко выше фолда;
- 1440×900: claim 177–374px, кнопка **279–350px**, nav-cta **122–154px**;
- EN 390: кнопка выше фолда, текст латиницей;
- скриншоты: `scripts/frontier105/landing_{mobile390,desktop1440,en_mobile390}.png`.

Дизайн-решение: claim над артом, а не под — гарантия «выше фолда» на обоих вьюпортах без вёрсточных акробатик (арт 674px @1440 сам съедает почти весь экран; claim под ним попал бы на границу 900px).

## 5. К5 — финал не платит завязке (подтверждено: узел d — 0 ссылок)

### Узел d (пир) связан в цепочку
Драматизированный финальный узел `elder_quest.nodes.d` («пир в твою честь», полное лечение) был недостижим — реальный финал сводился к «Награда: N д.» → victory_continue.

**Фикс**: `return_icon` при **успехе** сдачи иконы → узел `d` → `victory_continue` (итоги/продолжение). При провале сдачи — прежний выход. Механика подтверждена: `DialogueRunner._node()` выполняет `node.action` **до** чтения `node.choices` (DialogueRunner.js:62–89) — динамическая перезапись выбора того же узла работает (канонический паттерн vira_hub/ask_advance). Узел d больше не тупик: «Слава Богу.» → victory_continue.

### Суд пленника отыгран
Вор при оглушении «ждёт суд старосты» — но сцены суда не было. **Фикс**: `surrenderStolenItem` при `thiefDefeated='captured'` возвращает `trialNote` — суд старосты: покаяние пленника с **мотивом** («нанялся вынести святыню за серебро, заказчика же не выдал») и исторической рамкой (выдача княжьему наместнику по Судебнику 1497). Запись идёт и в ActionLog. Премия за поимку живьём (66.80, +20 д.) сохранена.

### Антагонист получил имя
`THIEF_NAMES` (пол выбирается в initThiefHunt, имя живёт в сейве): Онисим/Олеша/Шестач (муж.), Ждана/Милорода (жен.) — **намеренно вне пулов жителей** (антагонист не совпадает с живым селянином; проверено r143). `getThiefName()` с EN-формами; старые сейвы без thiefName — дефолт Онисим/Onisim. Встреча («{0} в тёмном плаще сжимает краденую икону») и реплика убеждения теперь называют имя; «благословение» иконокрада («Ладно! Пронеси тебя Бог, молодец!») заменено выдачей мотива («Пропадай серебро! Я нанялся святыню вынести, а заказчика и в глаза не видывал…») — наёмник, класс заложен в противостоянии «Болтовни вора» (раунд 47).

## 6. К6 — бюджеты реальны, критический путь ужат

### CI-гейт фиктивный → настоящий (подтверждено: continue-on-error:true + localhost)
Было: Lighthouse мерил `http://localhost:8000/` с `continue-on-error: true` — результат ни на что не влиял.

Стало (`.github/workflows/ci.yml`):
1. **Ожидание пересборки GitHub Pages** на push — поллинг ETag главной до 15 мин (иначе гейт мерял бы предыдущий деплой);
2. **Lighthouse по ПРОД**: `https://sosnowda.github.io/` + `https://sosnowda.github.io/en/`;
3. **Без continue-on-error** — провал ассертов валит CI.

Бюджеты (lighthouserc.json) — честные, по архиву 12 прод-прогонов аудита 66.104:

| Ось | Гейт | Прод-факт (архив) | Обоснование |
|---|---|---|---|
| performance | ≥ 0.85 | медиана 0.90 (контроль 66.103: 0.89–0.92) | запас 5 пунктов к медиане |
| accessibility | ≥ 0.95 | 1.0 | |
| best-practices | ≥ 0.75 | 0.77 | Яндекс.Метрика cookie, решение 66.88 |
| seo | ≥ 0.95 | 1.0 | |
| LCP | ≤ 3500 мс | медиана 3000 мс (2.75–4.45) | см. ниже |
| CLS | ≤ 0.1 | 0 | |

**Про LCP 2.5s vs 3.0s** (решение по К6): 2.5s на симулированной мобильной сети против GitHub Pages недостижим без пересмотра критического пути (TTFB Pages + композит шрифтов) — бумажный бюджет 2.5s был фиктивным вдвойне: не гейтился и не выполнялся. Зафиксирован **осознанный** бюджет: гейт 3.5s (медиана 3.0 + запас), **цель 2.5s** — куда двигаться (defer Метрики/шрифты). Игра (TBT 7.9–47.5s, canvas-приложение Phaser) гейтом сознательно не накрывается — бюджет игры отдельное решение владельца.

### Критический путь: снято противоречие «preload + loading=lazy»
Преплоад `assets/screenshots/01-title.webp` (первый скриншот галереи — низ страницы, `loading="lazy"`) удалён на RU+EN: ранний запрос конкурировал с LCP-героем за полосу на мобильном, а «мгновенную отрисовку при прокрутке» (цель 66.41) обеспечивает SW-кэш. Отзывчивый преплоад героя (imagesrcset/imagesizes, 66.90) цел — инвариант «preload === srcset источника» проверен r117/r142.
