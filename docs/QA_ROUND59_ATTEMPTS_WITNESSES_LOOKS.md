## Как работает «две попытки» (п.1)

- **Общий поиск локации** (`searchLocation`): первая неудача НЕ записывает локацию в `locationsSearched` — кнопка поиска остаётся, шансы второй попытки = Внимательность − 15 (вдобавок к ночному штрафу, если ночь). Вторая неудача закрывает локацию навсегда (текст «Ты вторично присмотрелся…»).
- **Видимые следы** (`examineFootprint`): первая неудача переводит след в состояние «заветрился» (счётчик `footprintRetries`), след остаётся на карте; вторая попытка — с −15; вторая неудача — след затирается (`'gone'`).
- Каждая попытка по-прежнему стоит 1 игровой час. Успех со второй попытки помечается строкой «(Вторая попытка: присмотрелся внимательнее — и след поддался.)» и «прибивает» вора на 2 часа (п.4 раунда 32 — без изменений).
- Эффект для «Следопыта»: ожидаемая вероятность прочесть след с двух попыток выросла с ~35 % до ~35 % + 0.65×(шанс−15) — для навыка 50 это ~50 % → ~64 %. Систематический поиск перестаёт быть хуже слепого.

## Свидетели (п.4): влияние на баланс

Пул вырос с 9 до 25 взрослых (кроме старосты и священника; дети исключены с раунда 44), свидетелей 10–15. Изменения в chase-sim (N=400 × 3 стратегии × 8 героев × 2 экономики):

| Стратегия | Победа | Поражение (вор скрылся) | Гибель героя |
|-----------|--------|--------------------------|--------------|
| Расспрос селян | 87–100 % | 0–13 % | 0 % |
| Слепой поиск | 19–45 % | 55–81 % | 0–1 % |
| «Следопыт» (по порядку) | 23–45 % | 50–77 % | 0–8 % |

- Вор по-прежнему уходит сам за ~22–23 ч (9–35) — базовое время не тронуто.
- С 10–15 свидетелями почти в любом доме можно получить наводку — стратегия расспроса стала ещё надёжнее (было 85–99 %).
- Баланс БОЯ и ВРЕМЕНИ УБЕГАНИЯ не менялся (приказ п.3 раунда 58: «баланс корректен»); единственная неувязка раунда 58 («Следопыт хуже слепого») закрыта п.1 этого раунда: две попытки делают систематический поиск конкурентным.

## Консоль и стабильность

- Чистый сеанс (открытие → генератор → деревня → локация «Ржаное поле»): **0 ошибок в консоли**.
- Известная особенность автоматизации: при принудительной подмене `Math.random` в тестах (пин к 0.99) Phaser 3.88 падает на создании Text-объектов — `Text._textureKey = UUID()` строится на Math.random, постоянное значение даёт дублирующийся ключ текстуры (`Texture key already in use: ffffffff-…`) и остановку `create()` сцены. Игра при этом восстанавливается собственным сторожем («цикл восстановлен»). В нормальной игре Math.random не подменяется — коллизии невозможны. Единичный такой эпизод наблюдался и на проде (WebGL-контекст headless), вне тестовых подмен — не воспроизводится; рекомендация: не переопределять Math.random в тестах, при желании — точечный `silentWarnings`/обновление Phaser.
