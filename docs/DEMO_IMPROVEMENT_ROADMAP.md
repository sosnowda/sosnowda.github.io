## 1. Контекст и текущее состояние

### 1.1 Что уже работает

Браузерное демо (`/game/`) построено на **Phaser 3.88.2** и полностью автономно от основного Godot-проекта. Из CDN загружается только сам Phaser, всё остальное — ES-модули, лежащие рядом. Текущая функциональность:

- **Сцены:** Boot → Title → Village → Combat / Character. Переходы стабильны, сохранения работают через `localStorage`.
- **Карта деревни** 26×18 тайлов (48×48 px каждый), генерируется процедурно в `data/world.js` через сетку символов: лес по периметру, река с мостом, четыре дома 2×2, шесть «атмосферных» деревьев. Проходимость — у травы и тропы, остальное блокирует коллайдер.
- **Персонаж игрока** — объект `Phaser.Physics.Arcade.Sprite` с текстурой `player`, генерируемой в `BootScene.makeFigure()` (тело + круглая головка + пояс). Ходьба — WASD/стрелки, взаимодействие — `E`. Камера следует за игроком с lerp 0.1.
- **Четыре NPC:** старейшина (беседа), купец (беседа + трава), раненый воин (беседа + лечение), разбойник (бой). У каждого — диалоговое дерево в `data/dialogue.js`.
- **Боевая система** на BRP (`systems/BRPEngine.js`): d100-проверки навыков, критический успех на `≤ skill/10`, провал на `≥96` при `skill<50`, урон с бонусом силы по таблице STR+SIZ. Четыре действия: меч, лук, уклонение, трава.
- **UI** — после удаления RexUI все компоненты (`createButton`, `createDialog`, `createFloatingText`) построены на чистом Phaser: Container + Graphics + Text. Заглушка `Loading.js` и `TestPage.js` лежат в репозитории, но в `index.html` не подключены.
- **PWA** — `manifest.json` + `sw.js` с network-first стратегией; `/game/` исключён из кеша, чтобы разработчики видели свежие правки сразу.

### 1.2 Главные недостатки (по приоритету)

1. **Визуальная бедность.** Все тайлы — плоские цветные квадраты с лёгким «шумом» из 6 тёмных пикселей. Персонажи — геометрические фигуры. Деревня выглядит как прототип из геймджема, а не как средневековая Русь.
2. **Нет анимаций ходьбы** — спрайт просто двигается с фиксированной текстурой. `setFlipX` есть, но `walk_down/walk_up/walk_left/walk_right` отсутствуют.
3. **Нет звука.** `AudioManager` существует, но в BootScene не загружается ни одного аудиофайла. Кнопки пытаются вызывать `playButtonClick()` — он молча ничего не делает.
4. **Бой статичен.** Спрайты бойцов не двигаются, эффект удара — только `cameras.main.shake(120, 0.004)`. Всплывающий текст урона есть, но без частиц крови/искр.
5. **Диалоги монотонные.** Все реплики — однострочный текст без портретов, без эффекта печатной машинки (хотя в `ui.js` есть `createStoryTextBox`, он не используется в основном диалоговом тракте).
6. **HUD минимален.** Только HP/MP/Меч в углу. Нет мини-карты, нет индикатора цели квеста, нет инвентаря.
7. **Узкий геймплей.** Один квест «победи разбойника», нет цикла отдыха/торговли/исследования. После победы над разбойником играть больше не во что.
8. **Нет мобильного управления.** На телефоне демо запускается, но играть невозможно — нет виртуального джойстика, нет кнопок действий.

### 1.3 Что не трогаем

- **Базовую BRP-логику** (`BRPEngine.js`, `Character.js`, `GameConfig.js`) — она проверена, соответствует правилам Basic Roleplaying и работает.
- **Структуру сцены** Boot → Title → Village → Combat → Character — она хорошая.
- **Лицензию CDN** — Phaser остаётся с jsdelivr.
- **Файл `sw.js`** — его стратегия network-first для `/game/` правильная.

## 2. Целевое видение демо v0.2

После доработки демо должно отвечать следующим критериям:

| Критерий | Сейчас (v0.1) | Цель (v0.2) |
|---|---|---|
| Стиль графики | Цветные квадраты | Pixelart top-down, единый LPC-стиль |
| Анимация ходьбы | Нет | 4 направления, 3-4 кадра на цикл |
| Звук | Молчание | Ambient-фон + 5-8 SFX + 2 музыкальных трека |
| Боевая анимация | Только shake | Подход-удар-отскок, частицы, вспышка |
| Портреты в диалогах | Нет | Mini-portrait 64×64 + эффект печатной машинки |
| HUD | Только HP/MP | HP/MP + мини-карта + трекер квеста + кнопка инвентаря |
| Управление | Только клавиатура | Клавиатура + виртуальный джойстик на мобильных |
| Время геймплея | 3-5 минут | 10-15 минут с побочными активностями |
| Вес страницы | ~200 KB | < 3 MB (со всеми ассетами) |
| Стабильность | 60 FPS на десктопе | 60 FPS на десктопе, 30+ FPS на мобильных |

Демо v0.2 — это **не мини-игра, а горизонтальный срез** основного Godot-проекта. Его задача — показать потенциальному игроку/спонсору «как будет выглядеть финальная игра», и подтвердить, что ключевые механики (BRP-бой, диалоги, исследование) работают в браузере.

## 3. Визуальный слой: тайлы, спрайты, эффекты

### 3.1 Тайлы карты деревни

**Текущее состояние:** 6 процедурных текстур 48×48 (`tile_grass`, `tile_path`, `tile_water`, `tile_forest`, `tile_rock`, `tile_house`), генерируемых в `BootScene.makeTile()` через `Phaser.GameObjects.Graphics`. Каждая текстура — заливка цветом + 6 случайных тёмных квадратов 3-8 px.

**Целевое состояние:** Единый pixelart-тайлсет в стиле **LPC (Liberated Pixel Cup)**, масштабированный до 48×48 px (либо переход на 32×32 с уменьшением `GAME.tileSize`). Подробные источники — в `ASSETS_RESEARCH.md`, раздел 1. Рекомендуемый набор:

- **LPC Tile Atlas** (CC-BY-SA 3.0 / GPL 3.0) — базовые террейны: трава, тропа, вода, переходы.
- **Fertile Soil Modular Village Pack** (CC0, itch.io) — деревянные избы, амбары, заборы. Ближайший к русской деревне стиль из бесплатных.
- **Kenney Roguelike Pack** (CC0) — камни, деревья, мосты (если нужен упрощённый запасной стиль без атрибуции).

**Шаги внедрения:**

1. Скачать LPC Tile Atlas с OpenGameArt (https://opengameart.org/content/lpc-tile-atlas). Распаковать в `game/public/assets/tiles/lpc/`.
2. Собрать в Photoshop/Aseprite единый атлас `village_atlas.png` размером 512×512 px, нарезав нужные тайлы из LPC. Использовать **только** тайлы, релевантные русской деревне: трава 4 варианта, тропа 4 варианта, вода + переходы (8 тайлов), лес 4 варианта, камень 2 варианта, изба 4 варианта (стена + крыша + дверь + окно).
3. Сохранить `village_atlas.json` с описанием帧 (frame descriptors) для Phaser.
4. В `BootScene.preload()` заменить `generateTextures()` на `this.load.atlas('village', 'assets/tiles/village_atlas.png', 'assets/tiles/village_atlas.json')`.
5. В `data/world.js` обновить `TILE_KEY`, чтобы он ссылался на帧 атласа, а не на отдельные текстуры. Например:
   ```js
   export const TILE_KEY = {
       '.': { texture: 'village', frame: 'grass_0' },
       ',': { texture: 'village', frame: 'path_0' },
       '~': { texture: 'village', frame: 'water_0' },
       'T': { texture: 'village', frame: 'forest_0' },
       '#': { texture: 'village', frame: 'rock_0' },
       'H': { texture: 'village', frame: 'house_wall' },
   };
   ```
6. В `VillageScene.create()` заменить `this.add.image(px, py, TILE_KEY[t])` на:
   ```js
   const tk = TILE_KEY[t];
   this.add.image(px, py, tk.texture, tk.frame);
   ```
7. Для домов 2×2 — вынести отрисовку в отдельный проход после основной карты, чтобы можно было рисовать «стена + крыша» одним тайлом 2×2 (или двумя тайлами 1×2: верх = крыша, низ = стена с дверью/окном).
8. Для анимации воды — завести 3帧 `water_0/water_1/water_2` и переключать их в `VillageScene.update()` каждые 300 мс через `this.time.addEvent({ delay: 300, loop: true, callback: ... })`.

**Оценка трудозатрат:** 8-10 часов (включая ручное составление атласа).

### 3.2 Спрайты персонажей

**Текущее состояние:** 7 фигурок (`player`, `npc_elder`, `npc_merchant`, `npc_soldier`, `npc_bandit`, `enemy_bandit`, `enemy_wolf`), каждая — тело 20×20 + голова 18 px + пояс 4 px. Размер 32×44 или 56×64. Никакой анимации.

**Целевое состояние:** Спрайты 64×64 px с **walk-анимацией в 4 направлениях** (по 3 кадра на цикл) и **attack-анимацией** (по 2 кадра). Единый LPC-стиль.

**Рекомендуемый источник:** **Universal LPC Spritesheet Character Generator** (https://sanderfrenken.github.io/Universal-LPC-Spritesheet-Character-Generator/) — веб-генератор, позволяющий собрать персонажа из модулей (тело, волосы, одежда, оружие). Лицензия CC-BY-SA 3.0 / GPL 3.0.

**Шаги внедрения:**

1. Через веб-генератор собрать 5 персонажей:
   - **Путник** (игрок) — мужская фигура, простая льняная рубаха, тёмные штаны, меч на поясе, русые волосы.
   - **Старейшина** — мужская фигура, седые волосы, длинная борода, тёмный кафтан, посох.
   - **Купец** — мужская фигура, рыжая борода, цветной кафтан, шапка.
   - **Раненый воин** — мужская фигура, доспех, перевязка на голове, опирается на меч.
   - **Разбойник** — мужская фигура, тёмная одежда, капюшон, секира.
2. Для волка — взять **LPC Wolf** (https://opengameart.org/content/lpc-wolf) — готовая анимация ходьбы и атаки, CC-BY-SA 3.0.
3. Скачать каждый набор spritesheet (формат PNG, обычно 832×1344 px, 13 колонок × 21 строка帧).
4. Нарезать через Aseprite на отдельные spritesheets по действиям: `walk_left.png`, `walk_right.png`, `walk_up.png`, `walk_down.png`, `attack_left.png` и т.д. Или загрузить весь атлас и использовать `Phaser.Animations.AnimationManager` с frame-диапазонами.
5. В `BootScene.preload()` загрузить атлас:
   ```js
   this.load.spritesheet('player', 'assets/sprites/player.png', { frameWidth: 64, frameHeight: 64 });
   ```
6. В `BootScene.create()` создать анимации:
   ```js
   this.anims.create({
       key: 'player_walk_down',
       frames: this.anims.generateFrameNumbers('player', { start: 0, end: 2 }),
       frameRate: 8, repeat: -1
   });
   // ... ещё 3 направления + attack_*
   ```
7. В `VillageScene.update()` запускать анимацию в зависимости от направления движения:
   ```js
   if (vy < 0) this.playerObj.play('player_walk_up', true);
   else if (vy > 0) this.playerObj.play('player_walk_down', true);
   else if (vx < 0) this.playerObj.play('player_walk_left', true);
   else if (vx > 0) this.playerObj.play('player_walk_right', true);
   else this.playerObj.anims.pause();
   ```
8. Для NPC — только `walk_down` и `idle` (3 кадра, frameRate 2, чтобы создать «дыхание»).
9. Для врагов в бою — `attack` анимация при ударе.

**Оценка трудозатрат:** 6-8 часов (генерация + нарезка + анимации + отладка).

### 3.3 Боевые эффекты

**Текущее состояние:** При ударе — `cameras.main.shake(120, 0.004)` + всплывающий текст `-${dmg}`. При промахе — ничего.

**Целевое состояние:**

- **Анимация подхода** — спрайт атакующего делает рывок к цели (tween за 150 мс), затем возвращается на исходную позицию (tween за 200 мс).
- **Анимация удара** — спрайт атакующего проигрывает `attack_*` анимацию (2 кадра, 100 мс каждый).
- **Flash-эффект на цели** — `Phaser.GameObjects.Sprite.setTintFill(0xff0000)` на 80 мс, затем возврат к `setTint(0xffffff)`.
- **Частицы крови** — `Phaser.GameObjects.Particles` с красным tint, 8-12 частиц на 400 мс.
- **Частицы искр** при блоке — `setTint(0xffaa00)` + 5-6 частиц.
- **Экранная вспышка** при критическом успехе — `cameras.main.flash(150, 255, 50, 50)`.
- **Camera shake** по силе удара: лёгкий = 0.003, средний = 0.006, крит = 0.010.

**Рекомендуемый источник частиц:** **Free Pixel Effects Pack** (https://kenney.nl/assets/particle-pack или OGA) — CC0, готовые PNG-спрайты для искр/крови/дыма.

**Шаги внедрения:**

1. Скачать particle pack, положить в `game/public/assets/effects/`.
2. Создать в `BootScene` текстуры частиц: `particle_blood`, `particle_spark`, `particle_dust`.
3. В `CombatScene` добавить метод `playHitEffect(x, y, type)` с тремя вариантами: `blood`, `spark`, `dust`.
4. В `playerAttack()` и `enemyTurn()` после расчёта урона вызывать `playHitEffect(tw.sprite.x, tw.sprite.y, 'blood')`.
5. Реализовать подход-отскок через `scene.tweens.add({ targets: attacker, x: target.x - 30, duration: 150, yoyo: true })`.

**Оценка трудозатрат:** 3-4 часа.

### 3.4 Портреты в диалогах

**Текущее состояние:** Диалог — окно 400 px с заголовком (имя говорящего) и текстом реплики. Никакого портрета.

**Целевое состояние:** К диалогу добавляется **портрет 96×96 px** слева от текста. Портреты рисуются вручную (или берутся из LPC-набора в увеличенном виде), в едином стиле «иконописное письмо» — чтобы подчеркнуть русскую тему.

**Шаги внедрения:**

1. Загрузить 5 портретов в `BootScene.preload()`: `portrait_elder`, `portrait_merchant`, `portrait_soldier`, `portrait_bandit`, `portrait_narrator` (для рассказчика).
2. В `data/dialogue.js` добавить поле `portrait` в каждый узел диалога:
   ```js
   a: { speaker: 'Старейшина', portrait: 'portrait_elder', text: 'Рад видеть тебя, путник...', choices: [...] }
   ```
3. В `DialogueRunner._node()` прокидывать portrait в `createDialog`.
4. В `createDialog` добавить отрисовку портрета: 96×96 px слева от заголовка, с золотой рамкой 2 px (стиль `RUS.border`).
5. Подключить эффект печатной машинки в `createDialog`: добавить опцию `typing: true`, при которой текст реплики печатается по 30 мс/символ. Использовать `scene.time.addEvent` с пошаговым увеличением длины текста.
6. Клик по диалогу во время печати — пропустить анимацию и показать весь текст сразу. Второй клик — открыть кнопки выбора.

**Оценка трудозатрат:** 4-5 часов.

### 3.5 Дополнительные объекты на карте

**Текущее состояние:** Дома — это 2×2 блока одного цвета. Деревья — одиночные тайлы `tile_forest`. Никаких декораций.

**Целевое состояние:** Дополнительные объекты-декорации:

- **Колодец** в центре деревни — отдельный спрайт 2×2 тайла, к которому можно подойти и нажать E (выводит флэш-текст «Свежая вода!» и восстанавливает 1 HP).
- **Часовня** — отдельный спрайт 3×3 тайла, место «сохранения» (восстанавливает HP/MP до максимума, как у старейшины).
- **Костёр** перед домом купца — анимированный спрайт (4 кадра пламени).
- **Тын/забор** — отдельные тайлы, чисто декоративные.
- **Сено/dry grass** вокруг амбара.
- **Цветные клумбы** у домов.

**Шаги внедрения:**

1. В `data/world.js` добавить новые символы карты: `'W'` — колодец, `'C'` — часовня, `'F'` — костёр, `'f'` — забор.
2. В `VillageScene.create()` после основной отрисовки карты — добавить объекты-декорации отдельным проходом (как NPC), чтобы они корректно отображались поверх тайлов.
3. Колодцу и часовне — назначить интерактивность через `setInteractive` + проверку расстояния в `updateNearestNPC()` (переименовать в `updateNearestInteractable()`).
4. Для костра — создать анимацию `fire_flicker` (4 кадра, 8 FPS, loop).

**Оценка трудозатрат:** 3-4 часа.

## 4. Звуковой слой: музыка и SFX

### 4.1 Музыка

**Текущее состояние:** `AudioManager` инициализируется, но `playMusic()` не вызывается ни в одной сцене.

**Целевое состояние:** Три музыкальных трека, переключающихся по сценам:

- **Главное меню** — `menu_theme.ogg`, спокойная тема с гуслями/флейтой.
- **Деревня** — `village_ambient.ogg`, ambient-петля с птицами и далёкими разговорами.
- **Бой** — `combat_theme.ogg`, динамичная тема с барабанами.

**Рекомендуемый источник:** **alkakrab Free Fantasy Medieval Ambient Music Pack** (https://alkakrab.itch.io/) — CC0, 5+ треков. Дополнительные треки с славянской интонацией — на OpenGameArt: «Vesna-Krasna» (для меню), «Leshy» (для леса), «The Training of the Russian Archers» (для боя). Подробности — `ASSETS_RESEARCH.md` раздел 5.

**Шаги внедрения:**

### 5.3 Вариативность боя

**Текущее состояние:** 4 действия — меч, лук, уклонение, трава. Нет магии, нет комбо, нет позиционирования.

**Целевое состояние:** Добавить:

- **Молитва** — тратит 3 MP, на следующий ход +20% к шансу попадания. Анимация — золотая вспышка над игроком.
- **Парирование** — если есть щит (инвентарь), можно парировать следующую атаку (50% шанс полностью блокировать урон).
- **Прицельный выстрел** — тратит 1 стрелу, +30% к шансу крита, но требует 1 ход на «подготовку» (следующий ход игрок пропускает).

### 5.4 Система отдыха

**Текущее состояние:** Восстановление HP/MP только через старейшину (благословение) и раненого воина (перевязка).

**Целевое состояние:** Игрок может **отдохнуть** у костра в деревне:

4. Если `quest.hoursPassed >= 24` — выводится сообщение «Ты провёл в походе больше дня...» (просто атмосфера, без механики).

**Оценка трудозатрас:** 1 час.

## 7. Технические улучшения

### 7.1 Оптимизация отрисовки тайлов

**Текущее состояние:** В `VillageScene.create()` каждый тайл создаётся как отдельный `Phaser.GameObjects.Image`. Для карты 26×18 = 468 объектов. Каждый кадр Phaser проверяет их на видимость.

**Целевое состояние:** Использовать `Phaser.GameObjects.Tilemap` или `Phaser.GameObjects.StaticTilemap` — это намного эффективнее, отрисовка одним батчем.

**Шаги внедрения:**

1. В `BootScene.preload()` загрузить атлас тайлов (см. раздел 3.1).
2. В `VillageScene.create()` — создать `Phaser.Tilemaps.Tilemap` из данных `buildMap()`.
3. Статичные слои (террейн, дома) — через `staticTilemap.createStaticLayer()`.
4. Динамичные слои (анимированная вода) — через `dynamicTilemap.createDynamicLayer()`.
5. Коллайдер — `physics.add.collider(player, staticLayer)` или `setCollisionByProperty({ solid: true })`.

**Оценка трудозатрат:** 3 часа.

### 7.2 Управление через мобильный виртуальный джойстик

**Текущее состояние:** Только клавиатура. На мобильных демо неиграбельно.

**Целевое состояние:** На touch-устройствах — виртуальный джойстик слева + кнопка «E» справа. На десктопе — скрыты.

**Шаги внедрения:**

1. Добавить проверку `Phaser.Input.Keyboard.KeyboardPlugin` — если нет клавиатуры, показать джойстик.
2. В `VillageScene.create()`:
   ```js
   this.joyStick = this.plugins.get('rexVirtualJoystick').add(this, {...});
   ```
   Или реализовать на чистом Phaser: круг + точка-ползунок, движущаяся по касанию.
3. В `update()` — если `this.joyStick`, то `vx, vy` берутся из `joyStick.forceX / 100` и `joyStick.forceY / 100`.
4. Кнопка действия — большой круг в правом нижнем углу, при касании вызывает `tryInteract()`.
5. В `CombatScene` — четыре кнопки действий становятся крупнее и выстраиваются в один ряд, чтобы помещаться на экране 360×640.

**Оценка трудозатрат:** 3-4 часа.

### 7.3 Сохранение прогресса

**Текущее состояние:** `SaveManager.saveGame(slot, data)` пишет в `localStorage`. Один слот, перезаписывается при каждом переходе между сценами.

**Целевое состояние:** Три слота автосейва + ручное сохранение:

- **Автосейв** (каждые 30 секунд): `slot=0`, перезаписывается.
- **Слот 1 / 2 / 3**: ручное сохранение через меню «Продолжить» → выбор слота → подтверждение.
- В `TitleScene` показывать для каждого слота: имя персонажа, уровень/HP, время последнего сохранения, краткое описание (например, «Перед боем с разбойником»).

**Шаги внедрения:**

1. В `SaveManager` добавить метод `listSaves()`, возвращающий массив с метаданными всех слотов.
2. В `TitleScene.continueGame()` — открыть новый диалог со списком слотов.
3. На каждом слоте — кнопки «Загрузить» и «Удалить».

**Оценка трудозатрат:** 3 часа.

**Текущее состояние:** Весь текст на русском, захардкожен в `data/dialogue.js` и в UI.

**Целевое состояние:** Вынести тексты в `data/i18n/ru.json` и `data/i18n/en.json`. Переключатель языка — в настройках. Для демо v0.2 — опционально, можно отложить до v0.3.

## 8. Производительность и совместимость

### 8.1 Вес ассетов

После перехода на реальные тайлы/спрайты нужно следить за общим весом:

- **Тайлы** — атлас 512×512 PNG, ~200 KB.
- **Спрайты персонажей** — 5×64×64 PNG spritesheets по ~50 KB = 250 KB.
- **Портреты** — 5×96×96 PNG, ~50 KB каждый = 250 KB.
- **Эффекты** — particle pack, ~100 KB.
- **Музыка** — 3 трека × 1.5 MB = 4.5 MB. Это самая тяжёлая часть.
- **SFX** — 10 файлов × 30 KB = 300 KB.

**Итого:** ~5.6 MB. Это приемлемо для веб-демо, но музыку можно сделать потоковой (streaming через Howler.js или `<audio>`-тег), чтобы не ждать загрузки.

### 8.2 Целевые платформы

- **Десктоп Chrome/Firefox/Safari** — 60 FPS, полное качество.
- **iPad / Android tablet** — 30+ FPS, качество спрайтов 1×.
- **Телефон в landscape** — 30+ FPS, упрощённые эффекты (без частиц).
- **Телефон в portrait** — показать плашку «Поверните устройство».

### 8.3 Тестирование

- **Lighthouse** — цель: Performance ≥ 70, Accessibility ≥ 90 (на главной странице сайта, не на демо).
- **Phaser Inspector** — для отладки сцен.
- **Прогон через BrowserStack** — на 5 устройствах: Chrome/Win, Safari/Mac, Firefox/Win, Chrome/Android, Safari/iOS.
